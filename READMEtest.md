## Prerequisites

| Requirement | Minimum version |
|---|---|
| Docker | 20.10+ |
| NVIDIA Container Toolkit (`nvidia-docker2`) | latest |
| NVIDIA GPU driver | ≥ 520 (CUDA 11.8 compatible) |
| Disk space | ~20 GB (image + data) |

Install the NVIDIA Container Toolkit if you haven't already:

```bash
distribution=$(. /etc/os-release; echo $ID$VERSION_ID)
curl -s -L https://nvidia.github.io/nvidia-docker/gpgkey | sudo apt-key add -
curl -s -L https://nvidia.github.io/nvidia-docker/$distribution/nvidia-docker.list \
    | sudo tee /etc/apt/sources.list.d/nvidia-docker.list
sudo apt-get update && sudo apt-get install -y nvidia-docker2
sudo systemctl restart docker
```

## Directory Layout

```
your-workspace/
├── Dockerfile               ← Docker build file
├── download_weights.sh      ← weight downloader (auto-run during build)
├── data/                    ← your dataset (Replica / ScanNet / custom)
│   └── room0/
│       ├── images/
│       ├── depth_images/
│       └── traj.txt
└── output/                  ← results will be written here
```

> **No manual weight download needed.** `download_weights.sh` is copied into the
> image and executed automatically during `docker build`. It uses
> [`gdown`](https://github.com/wkentaro/gdown) to pull the MobileSAMv2 weights
> (file ID `1dE-YAG-1mFCBmao2rHDp0n-PP4eH7SjE`) from Google Drive, extracts
> the archive, and places `l2.pt`, `mobile_sam.pt`, and `ObjectAwareModel.pt`
> into the correct submodule path automatically.

## Step 1 — Download MobileSAMv2 Weights

The weights are **not** downloaded during `docker build` — Google Drive rate-limits `gdown` when many builds run in parallel. Download them once on the host first.

```bash
# Download the zip from Google Drive (requires gdown)
pip install gdown
gdown --fuzzy "https://drive.google.com/file/d/1dE-YAG-1mFCBmao2rHDp0n-PP4eH7SjE/view" \
      -O /tmp/mobileSAMv2_weights.zip

# Extract the three .pt files to the weights directory
mkdir -p /home/zhanyuting/OpenGS-Fusion/submodules/MobileSAM/MobileSAMv2/weight
unzip -j /tmp/mobileSAMv2_weights.zip "*.pt" \
      -d /home/zhanyuting/OpenGS-Fusion/submodules/MobileSAM/MobileSAMv2/weight
```

Expected result:
```
submodules/MobileSAM/MobileSAMv2/weight/
├── l2.pt
├── mobile_sam.pt
└── ObjectAwareModel.pt
```

> If `gdown` still hits the rate limit, download the zip manually from the browser link above and extract it.

## Step 2 — Build the Docker Image

```bash
docker build -t opengs-fusion:latest .
```

What happens during the build:

1. System packages installed (PCL, CMake, …)
2. Miniconda installed; `opengsfusion` conda env created (Python 3.9)
3. PyTorch 2.0.0 + CUDA 11.8 installed
4. All Python packages from `requirements.txt` installed
5. Five submodules built and installed (`diff-gaussian-rasterization`, `simple-knn`, `MobileSAM`, `vdbfusion` from source, `fast_gicp`)

> ⚠️ The build takes **20–40 minutes** — `vdbfusion` builds OpenVDB + TBB + Boost from source.

## Step 3 — Prepare Your Dataset

### Replica

```
data/room0/
├── images/          ← RGB frames  (frame000000.jpg, …)
├── depth_images/    ← depth frames (depth000000.jpg, …)
└── traj.txt
```

### ScanNet

```
data/scene0046_00/
├── rgb/             ← 0.png, 1.png, …
├── depth/           ← 0.png, 1.png, …
├── pose/            ← 0.txt, 1.txt, …
└── traj.txt         ← generated by datasets_process/convert_pose_2_traj.py
```

### Custom dataset

Create a `config.txt` camera intrinsics file:

```
## camera parameters
W H fx fy cx cy depth_scale depth_trunc dataset_type
640 480 577.590698 578.729797 318.905426 242.683609 1000.0 5.0 scannet
```

Place it in `./configs/` inside the container (or mount it with `-v`).

## Step 4 — Run the Container

```bash
docker run --rm -it \
  --gpus all \
  --shm-size=16g \
  -v $(pwd)/data:/data \
  -v $(pwd)/output:/output \
  -v /home/zhanyuting/OpenGS-Fusion/submodules/MobileSAM/MobileSAMv2/weight:/workspace/OpenGS-Fusion/submodules/MobileSAM/MobileSAMv2/weight:ro \
  opengs-fusion:latest \
  bash
```

> `--shm-size=16g` is recommended because the mapping pipeline uses shared memory for multi-processing.

## Running the Pipeline

All commands below assume you are **inside** the running container. The `opengsfusion` conda environment is activated automatically by the container's `ENTRYPOINT`.

### Feature Extraction

Extracts 2-D SAM masks and CLIP features from RGB frames:

```bash
python mobilesamv2_clip.py \
    --image_folder /data/room0/images \
    --output_dir   /output/room0_features \
    --save_results
```

### 3D Mapping

Builds the semantic 3D Gaussian Splatting map:

```bash
python opengs_fusion.py \
    --dataset_path /data/room0 \
    --config       ./configs/Replica/caminfo.txt \
    --output_path  /output/room0_map \
    --save_results
```

### Using the pre-built bash scripts

```bash
# Replica
bash ./bash/train_replica_with_sem.sh

# ScanNet
bash ./bash/train_scannet_with_sem.sh
```

### Query / Visualisation

After mapping, launch the interactive open-vocabulary query interface:

**Replica**
```bash
python show_lang_embed.py \
    --dataset_path /data/office0 \
    --config       ./configs/Replica/caminfo.txt \
    --scene_npz    /output/office0/office0_default_each/gs_scene.npz \
    --dataset_type replica \
    --view_scale   2.0
```

**ScanNet**
```bash
python show_lang_embed.py \
    --dataset_path /data/scene0062_00 \
    --config       ./configs/Scannet/scene0062_00.txt \
    --scene_npz    /output/scene0062_00/default_with_sem/gs_scene.npz \
    --dataset_type scannet \
    --view_scale   3.0
```

#### Interactive key bindings

| Key | Action |
|---|---|
| **T** | Toggle colour / label mode |
| **J** | Highlight selected object |
| **K** | Screenshot |
| **O** | Print current camera info |
| **M** | Switch camera view |
| **P** | Downsample point cloud |
| **=** | Save current mask point cloud |
| **L** | Toggle voxel visualisation |

> ⚠️ The interactive viewer requires a **display**. When running on a headless server, use X11 forwarding:
> ```bash
> xhost +local:docker
> docker run --rm -it --gpus all \
>   -e DISPLAY=$DISPLAY -v /tmp/.X11-unix:/tmp/.X11-unix \
>   -v $(pwd)/data:/data -v $(pwd)/output:/output \
>   opengs-fusion:latest bash
> ```

## Using the Rerun Viewer

Add `--rerun_viewer` to see real-time Gaussian means and rendered frames via [rerun.io](https://rerun.io):

```bash
python opengs_fusion.py \
    --dataset_path /data/room0 \
    --config       ./configs/Replica/caminfo.txt \
    --output_path  /output/room0_map \
    --rerun_viewer
```

Then open the Rerun web viewer at `http://localhost:9090` from your host browser.

## Troubleshooting

**Weight download fails during `docker build`**  
The build host needs outbound HTTPS access to Google Drive. If you are behind a proxy or firewall, either configure Docker's proxy settings or download the weights manually and modify `download_weights.sh` to copy from a local path instead.

**`nvidia-smi` not found inside container**  
Make sure you passed `--gpus all` and that `nvidia-docker2` is installed on the host.

**`ModuleNotFoundError: No module named 'vdbfusion_pybind'` / `TypeError: incompatible constructor arguments`**  
The submodule contains a **custom fork** of vdbfusion with an extended `_VDBVolume` interface (extra `max_label`, `max_points`, `influence_voxel` args). The stock PyPI `vdbfusion==0.1.6` has a different, incompatible interface. The Dockerfile now builds the submodule from source with `setup.py build_ext --inplace`, placing the compiled `.so` directly in `submodules/vdbfusion/src/vdbfusion/pybind/` where `mp_VdbFusion.py` imports it. Rebuild the image to apply the fix:
```bash
docker build --no-cache -t opengs-fusion:latest .
```

**`ImportError` for fast_gicp**  
The C++ build requires PCL. If you see a missing `.so` error, rebuild the image or run inside the container:
```bash
cd /workspace/OpenGS-Fusion/submodules/fast_gicp/build
cmake .. && make -j$(nproc)
cd .. && python setup.py install --user
```

**Out-of-memory (OOM) during mapping**  
Reduce batch size in the config, or use a GPU with ≥ 16 GB VRAM (24 GB recommended for full Replica / ScanNet scenes).

## Running on ktv_lisa_da3 Data

All steps run inside the `opengs-fusion:latest` Docker image.  
The container WORKDIR is `/workspace/OpenGS-Fusion`; its entrypoint auto-activates the `opengsfusion` conda env.

### Step 0 — Convert DA3 output to Replica format

The conversion script is mounted from the host into the container.  
Source data and output directory are also mounted as volumes.

**Default mode** — NPZ resolution (280×504), images taken directly from NPZ:

```bash
docker run --rm \
  -v /home/zhanyuting/convert_da3_to_opengs.py:/workspace/OpenGS-Fusion/convert_da3_to_opengs.py \
  -v /home/zhanyuting/ktv_lisa_da3_output_ori:/src \
  -v /home/zhanyuting/ktv_lisa_opengs_input:/dst \
  opengs-fusion:latest \
  python convert_da3_to_opengs.py \
      --src /src \
      --dst /dst
```

**Full-resolution mode** — original 1250×702 RGB, depth resized to match:

```bash
docker run --rm \
  -v /home/zhanyuting/convert_da3_to_opengs.py:/workspace/OpenGS-Fusion/convert_da3_to_opengs.py \
  -v /home/zhanyuting/ktv_lisa_da3_output_ori:/src \
  -v /home/zhanyuting/ktv_lisa_opengs_input_fullres:/dst \
  opengs-fusion:latest \
  python convert_da3_to_opengs.py \
      --src     /src \
      --dst     /dst \
      --fullres
```

**All options:**

| Flag | Default | Description |
|---|---|---|
| `--src` | `/home/zhanyuting/ktv_lisa_da3_output_ori` | Source directory |
| `--dst` | `/home/zhanyuting/ktv_lisa_opengs_input` | Output directory |
| `--depth_scale` | `1000.0` | uint16 PNG encoding scale (value ÷ scale = metres) |
| `--depth_trunc` | `10.0` | Depth truncation in metres |
| `--fullres` | off | Use original 1250×702 RGB + resize depth to match |
| `--jpeg_quality` | `95` | JPEG quality for saved RGB frames |

Output layout after conversion:

```
ktv_lisa_opengs_input/
├── images/              ← frame000000.jpg … frame001237.jpg  (280×504)
├── depth_images/        ← depth000000.png … depth001237.png  (uint16)
├── traj.txt             ← 1238 c2w 4×4 matrices (16 values per line)
└── caminfo.txt          ← W H fx fy cx cy depth_scale depth_trunc replica
```
